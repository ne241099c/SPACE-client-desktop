# Senshu-Universe 本番接続デスクトップ版

2026-11-04 確定。添付の画面同梱方式の計画を、この文書で置き換える。

## 確定した方針

- Electron 内で https://senshu-universe.com を開く。React・サーバーは同梱しない。画面は Web の main の配信に追従する。
- Electron 一式は独立したリポジトリ SPACE-client-desktop に置く（2026-11-05 に SPACE-client のブランチから分離）。SPACE-client には bridge の受け口だけを置き、Web ビルド・Azure デプロイには Electron を持ち込まない。
- appId: jp.senshu-universe.app、製品名: Senshu-Universe。デモとは userData とセッションも分離する。
- 未読バッジは通知＋DM。集計関数の方針を変えることで、後から通知のみ・DM のみに変更できる。
- Windows はユーザー単位の NSIS と electron-updater。Mac は未署名の dmg/zip と手動更新案内。署名による自動更新への切替箇所は1か所にする。
- デモから安全設定・preload のバンドル方法・アイコン・Electron のテスト起動方法を流用する。LAN 探索・同梱サーバー・証明書の照合は持ち込まない。
- アプリを終了・OS がスリープ・ネットワークが切断されている間は新規の通知を受け取れない。ウィンドウを閉じる操作は非表示にし、通知接続を残す。

## 実装と確認の順番

1. 骨組み：リモート画面を開く、型検査・lint・Web ビルド、テスト用 HTTP サイトを Electron で開く。
2. 通信・安全：本番オリジンに限定した遷移・IPC、フレームの検証、権限拒否、外部リンク、失敗時の再試行。ローカルで REST/WS/SSE/PUT/fetch の Origin を測定する。本番の CORS 変更は不要。
3. 通知・常駐：既存の SSE 通知を非フォーカス時だけ OS へ送る。デスクトップでは hidden でも SSE を維持。通知クリック遷移、集計、ログアウト時のバッジ消去、トレイ・Dock・二重起動防止・ウィンドウ位置・ログイン時起動を確認する。
4. 更新・配布：起動時と6時間ごとの更新確認、最低版数、NSIS と Mac 配布設定、タグ起点の CI を用意する。ローカル更新サーバーを用いて更新状態を確認する。
5. 文書と実機確認：配布手順・Windows 手順・検証記録を書く。

各段階で自動確認と実機確認を区別し、実ログイン・実通知・Windows で未確認の項目を完了扱いにしない。現行の本番 Web に bridge がまだ配信されていない間は、アプリの通知・バッジは使えない。公開前にユーザーが Web の変更を配信する必要がある。

## 禁止事項

本番サーバー・Azure・CORS・環境設定を変更しない。push、マージ、タグ、GitHub リポジトリ作成、Release 公開を行わない。デモ版は変更しない。コメントと文書は日本語。認証情報・内部ホスト名を追加しない。
